# Template Embedding System

The Sail project uses a sophisticated template embedding system to bundle project templates directly into the executable, eliminating the need for external template files at runtime.

## Overview

The template embedding system converts a directory of template files into C++ code that can be compiled into the Sail binary. This ensures that `sail new` works out-of-the-box without requiring separate template installation.

## Architecture

```
Template Directory          CMake Processing           Generated Code         Runtime Usage
─────────────────          ───────────────────        ──────────────         ─────────────
sail_binary_template/   →  TemplateEmbedding.cmake  →  embedded_templates.*  →  TemplateManager
├── CMakeLists.txt                                     ├── .hpp                   ├── create_project()
├── README.md                                          └── .cpp                   ├── get_template_files()
├── src/                                                                          └── process_content()
└── include/
```

## Components

### 1. Template Source (`sail_binary_template/`)

The template directory contains a complete C++ project template with placeholder values:

```
sail_binary_template/
├── CMakeLists.txt           # Contains %%PROJECT_NAME%% placeholders
├── README.md               # Project documentation template
├── src/
│   ├── CMakeLists.txt
│   └── %%myproject%%.cpp   # Source files with name placeholders
├── include/
│   └── %%myproject%%/
│       └── %%myproject%%.hpp
├── test/
│   ├── CMakeLists.txt
│   └── test_%%myproject%%.cpp
└── cmake/                  # CMake utilities and configurations
```

**Placeholder System:**
- `%%PROJECT_NAME%%` → User's project name
- `%%project_name%%` → Lowercase version
- `%%PROJECT_NAME_UPPER%%` → Uppercase version
- `myproject` → Simple replacement for filenames and basic references

### 2. Build-Time Processing (`cmake/TemplateEmbedding.cmake`)

The CMake module `TemplateEmbedding.cmake` processes templates during build configuration:

#### Key Functions

**`sail_setup_template_embedding()`**
- Main entry point called from root CMakeLists.txt
- Discovers all template files
- Generates C++ source code
- Creates the `embedded_templates` library

**File Processing Pipeline:**
1. **Discovery**: Recursively finds all files in `sail_binary_template/`
2. **Filtering**: Excludes build artifacts, .git files, binaries
3. **Content Reading**: Reads each template file as text
4. **Escaping**: Escapes C++ string literals (quotes, newlines, etc.)
5. **Code Generation**: Creates C++ arrays with embedded content

#### Generated Output

**`embedded_templates.hpp`**:
```cpp
#pragma once
#include <array>
#include <string_view>

namespace sail::templates {
    struct TemplateFile {
        std::string_view path;     // Relative path in template
        std::string_view content;  // Escaped file content
        bool is_binary;            // Currently always false
    };
    
    extern const std::array<TemplateFile, 48> embedded_files;
    constexpr size_t file_count = 48;
}
```

**`embedded_templates.cpp`**:
```cpp
#include "embedded_templates.hpp"

namespace sail::templates {
    static constexpr std::string_view file_0_path = "CMakeLists.txt";
    static constexpr std::string_view file_0_content = "cmake_minimum_required(VERSION 3.21)\\n\\nproject(%%PROJECT_NAME%% VERSION 1.0.0)\\n...";
    
    static constexpr std::string_view file_1_path = "README.md";
    static constexpr std::string_view file_1_content = "# %%PROJECT_NAME%%\\n\\nA C++ project generated by Sail...";
    
    // ... more files ...
    
    const std::array<TemplateFile, 48> embedded_files = {{
        {.path=file_0_path, .content=file_0_content, .is_binary=false},
        {.path=file_1_path, .content=file_1_content, .is_binary=false},
        // ... more entries ...
    }};
}
```

#### Smart Rebuilding

The system includes intelligent dependency tracking:

- **Timestamp Checking**: Only regenerates if template files are newer than generated files
- **CMake Dependencies**: Uses `CMAKE_CONFIGURE_DEPENDS` to trigger reconfiguration when templates change
- **Build Integration**: Generated files are included in the build dependency graph

### 3. Runtime Interface (`sail::TemplateManager`)

The `TemplateManager` class provides the runtime interface to embedded templates:

#### Core Methods

**`TemplateManager()`**
- Loads embedded templates from the generated arrays
- Builds internal index for fast file lookup
- Validates template integrity

**`create_project(name, directory, overwrite)`**
- Creates a new project from embedded templates
- Processes all placeholder replacements
- Handles file system operations (directory creation, file writing)
- Validates project names and paths

**Template Processing**
- `process_template_content()`: Replaces placeholders in file content
- `create_directory_structure()`: Ensures parent directories exist
- `write_file()`: Safely writes files with overwrite protection

#### Placeholder Processing

The system supports multiple placeholder formats for flexibility:

```cpp
const std::vector<std::pair<std::string, std::string>> replacements = {
    {"myproject", project_name},              // Simple filename replacement
    {"%%myproject%%", project_name},          // Explicit placeholder
    {"%%PROJECT_NAME%%", project_name},       // Uppercase variant
    {"%%project_name%%", project_name},       // Lowercase variant  
    {"%%PROJECT_NAME_LOWER%%", lower_name},   // Forced lowercase
    {"%%PROJECT_NAME_UPPER%%", upper_name}    // Forced uppercase
};
```

## Integration Points

### CMake Integration

```cmake
# Root CMakeLists.txt
include(cmake/TemplateEmbedding.cmake)
sail_setup_template_embedding()

# Creates embedded_templates target automatically
# Links to sample_library for distribution
```

### Application Integration

```cpp
// In sail.cpp
#include <sail/template_manager.hpp>

int handle_new_command(const std::string& project_name, 
                      const std::filesystem::path& target_directory, 
                      bool overwrite) {
    try {
        sail::TemplateManager template_manager;
        return template_manager.create_project(project_name, target_directory, overwrite) 
            ? EXIT_SUCCESS : EXIT_FAILURE;
    } catch (const std::exception& e) {
        spdlog::error("Failed to create project: {}", e.what());
        return EXIT_FAILURE;
    }
}
```

## Benefits

### 1. **Self-Contained Distribution**
- No external template files required
- Single executable contains everything needed
- Eliminates installation and path issues

### 2. **Performance**
- Templates loaded at compile-time, not runtime
- No file system I/O for template access
- Fast project creation

### 3. **Reliability**
- Templates can't be corrupted or missing
- Version-locked templates (no drift between tool and templates)
- Consistent behavior across environments

### 4. **Developer Experience**
- Easy template updates (just modify files in `sail_binary_template/`)
- Automatic rebuilding when templates change
- Clear separation between template source and generated code

## Template Development

### Adding New Templates

1. Add files to `sail_binary_template/`
2. Use appropriate placeholders (`%%PROJECT_NAME%%`, etc.)
3. Build project - templates automatically embedded
4. Test with `sail new test_project`

### Placeholder Guidelines

- Use `%%PROJECT_NAME%%` for most text replacements
- Use `myproject` for simple filename replacements
- Use `%%PROJECT_NAME_UPPER%%` for preprocessor defines
- Use `%%PROJECT_NAME_LOWER%%` for lowercase identifiers

### File Filtering

The system automatically excludes:
- `.git*` files and directories
- `build/` and `out/` directories  
- `.DS_Store` and `.gitkeep` files
- Binary files (based on extension)

### Debugging

- Check generated files in `build/generated_templates/`
- Use `cmake --build build --verbose` to see processing
- Template count displayed during build: "Generated embedded templates: N files"

## Technical Details

### Memory Usage
- Templates stored as `constexpr std::string_view` (zero runtime allocation)
- Content stored in program's data segment
- Efficient memory usage (no duplication)

### Build Performance
- Only regenerates when templates actually change
- Minimal impact on clean builds
- Incremental builds skip template processing when unchanged

### Limitations
- Binary files not currently supported
- Large templates increase executable size
- Template changes require rebuild (by design)

## Troubleshooting

### Common Issues

**"Template directory not found"**
- Ensure `sail_binary_template/` exists in project root
- Check CMake is running from correct directory

**"No templates embedded"**  
- Verify template directory has non-binary files
- Check file filtering rules aren't excluding your templates

**"Build fails after template changes"**
- Clean and rebuild: `cmake --build build --target clean && cmake --build build`
- Check for syntax errors in generated C++ code

### Debugging Generated Code

```bash
# View generated header
cat build/generated_templates/embedded_templates.hpp

# View generated source (first few templates)  
head -50 build/generated_templates/embedded_templates.cpp

# Check template count
grep -o "file_count = [0-9]*" build/generated_templates/embedded_templates.hpp
```
